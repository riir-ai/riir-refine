## What lands

1. **R1 `debug-level-gated-computation`** (rust_perf, complexity, BENCHABLE): a hot-path value computed into a binding whose ONLY consumer is a `debug!`/`trace!` call runs even when the level is off — the binding is a real statement, and log's runtime `max_level` is an atomic load LLVM cannot const-fold, so the computation executes every iteration. Fix: `log_enabled!` gate (or move the computation into the macro's lazy args). Mechanism home: the perf-book Logging and Debugging chapter. context_note carries the #143684 wall-time-vs-icount rider.
2. **R2 `macro-generated-code-optimize-at-generation-point`** (rust_perf, complexity, NotBenchable suggest-only, annotated): proc-macro emitters trim/dedupe generated code AT GENERATION, measure with `-Zmacro-stats`; downstream optimization machinery must reconstruct what the emitter already knew.
3. **R3 `large-api-dependency-mostly-unused-hint`** (dist, NEW family `BuildTime`, suggest-only): a manifest depending on a known-large API crate (`windows`, `windows-sys`, `rustix`, `aws-sdk-*` prefix) should measure `-Zhint-mostly-unused`. Detector: dependency names collected from any `*dependencies` section; the fix lives in `.cargo/config.toml` rustflags (out-of-manifest — the fixed fixture IS the config snippet, recorded honestly in notes).
