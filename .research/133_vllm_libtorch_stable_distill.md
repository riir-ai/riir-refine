## What it is

The kernel layer of the highest-throughput production LLM engine. The `libtorch_stable/` tree is the classic hand-written kernel collection (marlin, gptq, sampler, topk, moe, cache, layernorm, MLA fusion kernels for DeepSeek-V4 / Kimi-K3 / MiniMax-M3) kept on a stable ABI independent of torch version. The new `cooperative_topk` + `persistent_topk` machinery is a fresh vocab-scale top-k family with a documented manifest-bug history — unusually rich decision content with the failure modes written out in comments by the fix authors.

## Verdict

**YES, grade A-.** Production-deployed kernels with in-source measured sweeps (`fp32_router_gemm` B300 tables with honest revision history), a documented-bug heritage (the topk comments narrate two REAL manifested bugs and their fixes — the exact "mistakes/ post-mortem" grade that made B106's MTPLX batch high-yield), and multiple rules directly applicable to our stack (router GEMM register relief at M=1..32 = qwen3.8's MoE gate shape; ballot tie-rank + spin-barrier co-residency + capture-init for any future sampling/persistent kernel; UE8M0 PoT scale bytes beside our Issue-845 work; the MLA qknorm-rope-kv-insert fusion family beside our kimi-k3/qwen38 decode paths).

Not A because: a meaningful slice of the freshest machinery (cooperative_topk wholesale, PDL waits, TMEM attn_res) is Hopper/Blackwell-only — decision content survives engine-agnostically for some (recorded below), but the as-written kernels cannot run on our Ada 4090 / Vulkan / M3 surfaces.

## Domain routing

`kernel_opt` (GPU kernels + host orchestration). The tempting wrong domain: none — this is unambiguously kernel territory. The `rust/` dir (vLLM's new Rust bench/chat/server CLI stack) was scoped and SKIPPED for kernel_opt; it is application-level tokio/axum code (the `bench` suite is a serving benchmark, not kernel code) — a future low-priority `rust_perf` source at best, recorded as unread remainder, not graded.

## GOAT candidate test (#1, `spin-barrier-needs-co-residency-capped-launch`)

1. **Benchable:** measured-GOAT distillation shape (B49/B52 precedent) — the rule's content is the launch contract; a G1 gate = the headroom/cap/fallback arithmetic pinned by a unit test over occupancy values, plus the refuse-loudly path. Not a Pareto-bench rule (it is correctness-bearing).
2. **Exact semantics:** integer arithmetic — bit-exact trivially.
3. **Magnitude story:** a deadlocked spin barrier is an infinite-regress hang; the fallback converts a hang into a slower-but-correct launch. The comments document BOTH failure directions as manifested bugs.
4. **Deterministic:** pure function of (num_sms, occupancy, ctas_per_group, needs_cooperative).

Alternative GOAT: #5 (algebraic cancellation) is the only candidate with a clean microbench shape (tolerance-gated — output bits differ from the divide-then-norm path by documented rounding, never bit-identity).

## Upstream hazard ledger (recorded per the B103/B107 discipline; not our bugs to fix)

- **H1 (the systemic one): silent tie-buffer overflow drops, 4 sites / one class** — persistent_topk.cuh:294/402, :512/582, :1190/1267, topk_histogram_4096.cuh:470-485 all `__builtin_expect(pos < CAP, 1)` with silent drop on overflow. Coarse ties differing in low fp32 bits make the emitted top-K WRONG (not merely tie-different); the 4096 path's kept subset is atomic-arrival-order nondeterministic. The cooperative path FIXED its instance with the clamp rationale comment (cooperative_topk.cuh:404-406); the four sites above remain. R18's sampler fit-guard is the correct contract — encoded into the rule at mine time.
- **H2: `VLLM_STABLE_DISPATCH_GROUP_SIZE` ladder has no default arm** (dispatch_utils.h:118-125) — unsupported group_size falls through with NO error and NO execution. The silent-zero class; our `compile_error!`/loud-refusal doctrine is the contrast.
- **H3: cross-tier router numeric divergence** (grouped_topk_kernels.cu:1165 vs :1029-1032) — the warp tier re-derives unbiased weights by `(σ(x)+b) − b` while the block tier reads the stored value; ≠ in fp32 → same token routes differently per tier. Relevant to OUR router code (sigmoid-not-softmax + scalar-projection discipline).
- **H4 (lane A): KDA kernel fires the PDL trigger BEFORE its output stores** (fused_kda_decode_kernel.cu:660-664 vs out writes :683-734) — contradicts the sibling MLA kernel's own documented contract (kimi :678-680). Safe only if every consumer waits its own dependency sync; early triggers compose down a PDL chain.
- **H5 (lane A): reads-before-wait rely on scheduler ordering, not PDL** (kimi decode reads slot_mapping/scales/cos_sin before its wait; cache-slot warps read kv_c/k_pe with no wait).
- **H6 (lane A): process-lifetime `static` SM-version caches** in template launchers (kimi :821, dsv4 :603, minimax :550, minimax_reduce_rms :652/:713) — first-current-device capability cached for the process; wrong on heterogeneous multi-GPU (B56 class).
- **H7: fast-math inconsistency in router math** — `__expf` in moeSigmoid vs `expf` in moeSoftmax (topk_softmax_kernels.cu:157 vs :119); `__logf/__expf` in softplus-sqrt scoring. Tolerable for routing; would violate any batch-invariant contract (R6 interplay).
- **H8: perf-side miss** — radix stage-3 collect does per-element atomicAdd without warp aggregation (persistent_topk.cuh:832-838) — the anti-instance of rule #17, same file.
- Minor: documented-fixed bugs (moe_align lora-slot grid off-by-one = vllm#32277 class; the R2 memset race; the cooperative le_full hole), the sampler's flagged `union` type-pun UB (sampler.cu:112-116) vs the honest deferred-reinterpret in cache_kernels_fused.cu:119-122, +inf-LSE-mapped-to-−inf (merge_attn_states.cu:96-97), lane-A's misleading MiniMax PDL comment + dubious `__syncwarp` around shuffles + dsv4's const_cast of `q`.
