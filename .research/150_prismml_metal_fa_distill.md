## The five rules (all kernel_opt, first-priority Metal domain)

1. `kv-dequant-materialization-batch-threshold-gate` (N) — commit `63b64a50` (#27438, Georgi Gerganov, 2026-08-20). The KV dequant-to-f16 materialization is gated `ne[1] < 32 → false` inside `ggml_metal_op_flash_attn_ext_use_kv_f16` (ggml-metal-ops.cpp:2809-2815 at the pin): "depending on compute/bandwidth ratio, dequant to f16 kv is not always beneficial" + "TODO: tune per device". Companion (same commit, :2977-2982): the wide-form temp buffer is RESERVED even when the gate declines — "always reserve the temp buffer to avoid graph reallocations". Two decision contents in one commit: amortization-gated materialization + allocation-stability over conditional allocation.

2. `offline-device-tuned-table-dispatch` (K) + 3. `tuned-config-resource-limit-fallback` (K) — commit `f280b269` (#26570, YiChen Lv, 2026-08-25). Per-device (Q, NE) FA-vec tuning tables generated by a new tuner tool (`ggml-metal-tuning.cpp:65-68`: "Generated by `ggml-metal-tuning fa-vec`; do not hand-edit. ... To retune or add a device, re-run the sweep and paste its output."), keyed (device_id, gpu_family, dtype, dk, dv, ne11_bucket, ne01_bucket), dispatched through exact → ne11-collapsed domain default → family representative SKU → baseline ("short KV: attention is a small slice of the step, left to baseline" :1046-1049); 53 f16 instantiations "vec 80 -> 133". Dispatch-time safety (ggml-metal-ops.cpp:3440-3444): "fall back to baseline (Q=1) if the tuned config exceeds threadgroup memory" — `FATTN_SMEM(nsg) > props_dev->max_theadgroup_memory_size` (the source's 'theadgroup' typo quoted verbatim) → `fa_vec_baseline_cfg`. Tuner discipline from the commit message: pointwise no-harm gate, median timing per cell, "cool down and re-measure the dirty window on thermal drift", "fold family table into a per-family representative SKU".

4. `quantize-scale-math-wide-precision-denorm-safe` (N) — commit `78ec4c37` (#27413, Jeff Bolz, 2026-08-20). Vulkan FA MMQ: "Codex found that qd could be a denorm and 1/qd would overflow." The dynamic-quantize transform (amax reduce, amax/127, 1/qd, round) re-typed from the kernel's FLOAT_TYPE (fp16) to fp32 (flash_attn.comp:129-130 at the pin: `const float qd = amax / 127.0f;` + `const float qd_inv = qd != 0.0f ? 1.0f / qd : 0.0f;`); stored payload + header scale stay narrow. Correctness axis — no tolerance argument applies.

5. `extent-clamped-operand-views-partial-k-tile` (A) — commit `a3027337` (#27450, Georgi Gerganov, 2026-08-20). Metal Tensor-API matmul with static tile K read OOB on partial tails: "On the last, partial K tile (ne00 % 32 != 0) the src1 slice extends past the K extent of the tensor, and the op reads those out-of-bounds elements (undefined behavior per the MSL specification, section 2.22.2). Depending on stale memory contents, this corrupted the result or produced NaN." Fix: `dynamic_extent` descriptor (mul_mm.metal:71) + per-iteration operand-view extents clamped `min(N_MM_NK_TOTAL, K - loop_k)` (:123-127), degenerating to the full tile on aligned K ("a handful of integer ops per iteration"). Provenance: "Assisted-by: pi:llama.cpp/Qwen3.8-27B" — a model-assisted kernel fix landed in the opponent's tree.
