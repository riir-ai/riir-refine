## Mechanism map (what the repo does)

A deterministic egress floor for tool-using agents (`floor.py`): every side-effecting tool call passes a tier ladder (read-only → content tier → access-grant principal → taint-novel TARGET recovery → payload taint → integrity tier → sentinel → destructive → credential → allow). Where an action goes is read from the TOOLS' TYPED RETURNS: a scalar leaf of a typed tool-output object is an IDENTITY leaf iff its JSON-schema `format` is a constrained identity format (email/uri/uuid/ipv4…) or its field NAME is a routing role (`index_identity_leaves`, `floor.py:218`); free-text leaves contribute NOTHING ("the exfil channel stays shut"). Taint (Eq. 1, `floor.py:112-128`): significant tokens = emails + URLs + normalized 4..120-char whole values; taint-novel = present in tool output ∧ absent from user text → attacker-derived. The recovery ladder for a taint-novel target: delegation rules (referent-bound, user-referent, self-owned) → two-view judge referral (`judge.py:271-277` — routing view then payload view, allow only if BOTH clear, min score) **vetoed when a target lies in a removed span** (`no_target_in_injection_span`, `floor.py:1058`: the judge may restore a refused call, never one whose target appears in the sanitizer's removed text) → more delegation → BLOCK. The ingress sanitizer (`sanitizer.py`) removes forged chat-template turns, injection-template regions, agent-addressed regions, and payee-change claims — every removed region appended verbatim to `span_sink` as the veto's evidence — and its "Linear-time matching" section (`sanitizer.py:152-202`) restructures the reference gate's quadratic scans to linear with the SAME Match objects, spans, and order.
