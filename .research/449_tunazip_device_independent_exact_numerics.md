## What the source is

A fork of Tufa Labs' tufazip (163M-param transformer that TRAINS WHILE COMPRESSING, NNCP lineage, arithmetic-coded output) whose entire contribution is making the train-while-coding arithmetic **bit-exact across GPU models**. Tufazip refuses to run off 2× B200 + exact CUDA/cuDNN versions; the blog shows a float-mode file decodes 99.9% garbage on any other GPU (first wrong token 1–2). tunazip's deterministic mode decodes byte-exact across H100→B200/A100/L40S/A10/T4. The mechanism inventory (every file read at the pin except the disclosed residue):

- **Exact matmul** (`detops/gemm.py`): `grid_round` operands to ≤16 significant bits with ONE shared power-of-two scale per a-row / b-column (`peak_of` = ±inf-norm over dim −1/−2), then f64 matmul. Precondition refused LOUD (gemm.py:23-24): `if a.shape[-1] * 2 ** (bits_a + bits_b) > FLOAT64_EXACT_INTEGER_LIMIT` (`2**53`) → `ValueError("inner dimension … overflows the exact float64 range")`. Consequence: every product and every partial sum is exactly representable, so ACCUMULATION ORDER CANNOT CHANGE THE RESULT.
- **Exact sums** (`detops/fixed.py:83-89` `exact_sum`): quantize to `bits = min(SUM_FRACTION_BITS=40, INT64_SUM_BITS=62 − (terms−1).bit_length())`, cast int64, `sum(dim)`, rescale — the accumulation runs in INTEGER addition. ⚠ wording pinned by the reviewer: this path TRADES the significand budget for an int64 OVERFLOW budget (`62 − log2 terms` bits), and the quantization to that width is itself lossy — never "free exactness".
- **Exact powers of two without libm** (`fixed.py:33-35` `peak_scales`, `functions.py:28`): `__longlong_as_double(((long long)(BITS − exponent) + 1023LL) << 52)` — the scale constants are constructed by exponent-field bit manipulation, device-identical by construction.
- **Anti-contraction per intrinsic** (every CUDA source string): `__dmul_rn` / `__dadd_rn` everywhere + `nearbyint`; blog footnote 7 verbatim: "The CUDA kernels use `__dmul_rn` and `__dadd_rn` so the compiler can't fuse a multiply and an add into one differently-rounded instruction." Cross-target constants cross as HEX FLOAT literals (`fused.py:12-13` `float(value).hex()` injected into the kernel source) so host and device parse identical bits.
- **Portable transcendental** (`detops/elementwise.py` `det_exp`): two-part ln2 argument reduction (INV_LN2/LN2_HI/LN2_LO as hex constants), `k = nearbyint(__dmul_rn(x, INV_LN2))`, Horner over exact rational coefficients (`EXP_COEFFICIENTS = [float(Fraction(1, factorial(n))) for n in range(14)]`), clamp ±700, final scaling by the exponent-bit pow2; host twin replays the SAME op order in torch f64.
- **Counter-based RNG with stream-key domain separation** (`detops/rng.py`): splitmix64 (golden-ratio constants) over `counter + key`; `stream_key(*parts)` folds domain parts (`stream_key(seed, INIT_DOMAIN, param_index)`, per-call dropout keys `stream_key(seed, DROPOUT_DOMAIN, call_index)` at detmodel.py:99-103); dropout threshold derived from probability × 2^24; 12-uniform normal draws.
- **Offline higher-precision constants** (`elementwise.py:55-103`): RoPE cos/sin tables computed in Decimal prec=60 (Machin π), folded once into runtime f64→f32 buffers.
- **Written-out Adam** (`detops/optim.py`): every op explicit with the same anti-contraction; even the clip norm runs `exact_sum` (the int64 path).
- **Their own test battery** (`tests/test_detops.py`): `test_matmul_matches_big_integer_reference` — arbitrary-precision `Fraction` oracle, bitwise `uint32` equality, adversarial cases (logspace ±12 scales, zeros, worst-case constants); **`test_op_hashes_independent_of_thread_count`** — the full op-hash battery must be IDENTICAL at N torch threads vs 1 thread (order-insensitivity pinned as a test); `test_deterministic_round_trip` end-to-end; `assert_matches_float` — det vs float within `GRADIENT_TOLERANCE = 1e-6` (the QUALITY leg, forward and backward).

The exactness arithmetic independently re-derived (verdict round 0 + reviewer round 2 concur): shared-exponent operands bound each product's mantissa to b1+b2 bits and its dynamic range to 2^(b1+b2); summing `inner` such products costs at most log2(inner) extra top bits, so the exactness condition is `inner_dim × 2^(b1+b2) ≤ 2^p` (p = significand width).

## R1 — the lead, as adjudicated

**Rust shape:** quantize operands to a bounded mantissa width under a shared power-of-two per-row/column scale (round-to-nearest, loud precondition refusal), accumulate in f64 (or the int64 variant with its OWN overflow budget `62 − log2 terms`), then ANY reduction order is bit-identical — verified against an exact integer reference.

**The distinct-role sentence (verbatim into the entry's distinct-from clause; the fold-guard agreed in verdict round 2):** *The neighbours either PIN the reduction order (`shape-only-plan-row-invariant-kernel` gpu_56/B188, and the house katgpt-rs Issue 940 law) or use exactness to LICENSE a narrower dtype (`exact-widening-enables-fp16-pv-accumulation` gpu_48/B178, `deferred-bias-ternary-dp4a-exact-isum` gpu_49/B180); R1 is the third posture — bounding the operand mantissas makes every reduction order (parallel, atomic, split-K, tree) produce identical bits, freeing the order instead of pinning it or spending the exactness on dtype.*

**Budget rows (reviewer-re-derived, round 2):** `inner_dim × 2^(b1+b2) ≤ 2^p`, p = significand width.
- **f64 (p=53):** 16+16-bit operands → inner ≤ 2^21 (the blog's row — serves the ORACLE/G5-reference lane where f64 is the reference substrate).
- **f32 (p=24):** 8-bit operands → inner ≤ 2^8 = 256; 12+12 → inner ≤ 2^0, i.e. NO accumulation room — refuse. Our serving surfaces (Metal/cubecl MSL, the `dot_f32_ordered` paths, the 1186 CQ3 lane) are f32: the directly-transferable band is the low-bit-operand class or the int64-accumulator variant, NOT the f64 16/16 row.

**The lossy side (round-1 correction, binding):** a shared power-of-two exponent per row/column rounds small elements adjacent to a large row maximum down to zero or a coarse grid — a LOSSY transform. The lossy-surface promotion rule binds: per-family, deployed-path behavior (conditional retention), never bit-equality-against-i128 alone (that certifies DETERMINISM, not QUALITY). The losing regime, named in-rule: wide dynamic range WITHIN a row/column. Quality leg template: their `assert_matches_float` (det vs float ≤ 1e-6, forward AND backward); stress shape: their `wide_range` logspace-±12 generator.

**Bench posture (pre-registered demotion):** G1 = cross-order bit-identity — quantized-f64 unrolled-4 vs sequential vs REVERSED, all `to_bits`-equal to each other AND to an i128 exact reference, plus the thread-invariance shape (their `test_op_hashes_independent_of_thread_count` is the fixture template).
