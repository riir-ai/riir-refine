## Parallel-session addendum — the aarch64 half (2026-09-02, the M3 lane; collision yielded per push-wins)

A second session ran this same batch concurrently (the collision class the AGENTS.md ledger records — their `43a3aca` landed and pushed mid-session; mine was uncommitted at the same paths). **Yielded wholesale** — their rule, gates, pins, and docs stand. This addendum preserves MY lane's unique data: the same probe methodology on **aarch64 (M3 Max, rustc 1.97.0, macOS 26.6.2)**, which both complements and partially bounds their x86_64 record:

1. **The split re-merges on aarch64 for the value-returning shape — asm-pinned.** Their record: on x86_64 the split survives as two DIRECT `jmp h_*` tail-jumps. My probe: with the same source-level split (`if c { t[0](acc) } else { t[1](acc) }` through a runtime table) on aarch64, LLVM tail-merges the pair into ONE `blr` on BOTH arms — fixed arm compiles to `csel x8, x20, x19, ne; blr x8` (identical site shape to the merged arm). The x86_64 no-re-merge result is ABI/backend-specific, not portable truth; aarch64 consumers should not assume split sites persist.
2. **A third transform their rule does not cover: the handler-PAIR HOIST.** Their negative control (runtime-opaque targets, x86_64): split-vs-merged = 0.95–1.00× — splitting buys nothing, route to `dyn-to-enum`. My aarch64 probe of a DIFFERENT fix — hoist both table entries once before the loop, select between registers (`let f0 = table[0]; let f1 = table[1];` then `acc = if c { f0(acc) } else { f1(acc) };`) — measured **LCG-random 0.837–0.840 (fixed wins ~16–19%), verdict-stable ×3; period-16 0.988–1.004 and alternation 0.990–1.003 (Tie band)**. The corpus validator on the random-regime harness: **ParetoDominant 2/0/0 — 1.23×/1.22× at 10K/1M dispatches (band 1.19–1.23× across 3 runs), 0/0 allocs, alloc-det stable ×3.** Mechanism (asm-pinned): the aarch64 merged form keeps an IN-LOOP indexed load (`csel x8, xzr, x22, ne; ldr x8, [x19, x8]; blr x8` — DestProp's merged-load shape; the classic per-dispatch `HANDLERS[op](..)` idiom is the buggy form), and the hoist eliminates it; the win shows only on unpredictable streams (a learnable stream lets the single site's indirect predictor hide the load).
3. **Candidate 2 corroboration (aarch64):** their x86_64 probe of `hot-dispatch-gpr-arg-budget` read Tie (1.009/0.999×); my independent aarch64 probe (9-int-arg vs 8-int+1-f64 `#[inline(never)]` handler, G1 bit-exact, 1M calls) read **1.000 flat** (276.1 vs 276.2 µs). Two ABIs, two boxes, same kill — the queued-kill-free disposition is cross-arch corroborated.
