## What the source is

The NVIDIA megakernels of the SGLang framework: for each covered model, the small-batch decode step as ONE co-resident launch — hand-rolled CUDA (NVRTC-compiled `.cu`) + CuTe DSL Python kernels handing outputs to each other "through mailboxes and programmatic dependent launch instead of through per-op boundaries". Three model families: DeepSeek-V4.1-Flash (TP4 GB300/SM103, DSpark speculative verify steps), Qwen3.5-397B-A17B NVFP4 (TP8, MTP/EAGLE verify, GDN+attention), Kimi K3 packed-MXFP4 (TP8, 93-layer decode, experimental adapter). README design laws: **built at load** (nothing compiled/allocated inside a step), **graph-safe coverage** (a step is covered by forward mode + row count alone, so every rank decides the same and a captured graph replays the capture-time decision), **fail-stop synchronization** (cross-GPU waits carry a deadline below SGLang's watchdog; a missed deadline "stores through address 0x0 and traps"; "no token from a failed step is returned"), **no silent fallback** (unsupported setup stops the server at startup listing every reason). Completeness signals all green: kernel/unit/e2e test batteries (stock-vs-plugin bit-parity canaries, poisoned-scales tests, `test_deepseek_v41_fail_stop.py`, `test_kimi_k3_deadline.py`, a GSM8K quality protocol matched against a frozen stock reference), benchmark dir, CI. WIP signals: the README's own "Experimental" badge — "bounded functional and quality evidence; it does not claim performance" — so NO perf numbers anywhere; graded at MODULE level, everything read is complete. Hardware regime: GB300/SM103 + NVLink symmetric-memory peer buffers + `multimem` multicast + PDL (sm_90+) — NOT our fleet's silicon (M3 Metal / single-4090 sm_89).
