- What it is: the first open-source infra for **continual self-improving agents** — connects agent inference, feedback, learning, and **versioned delivery**. Two learning surfaces: model **weights** (Slime/SGLang training) and the agent **harness** (prompts/rules/skills/code). Four-step loop: Serve → Observe → Grow → Commit. Scenarios = named workload channels with per-scenario recording, training state, and release chains. Recipes encode HOW the improvement loop executes (GEPA / TTTD / SAO / skillclaw / openclawrl ships as recipe folders).

## The five primitives worth taking (code-pinned @ ecec4e2)

| # | Primitive | Where in reef | The transferable shape |
|---|---|---|---|
| P1 | **Per-kind admission gates on structural mutation proposals** | `reef/harness/tree/nodes.py` — "Each kind's plugin body is its admission gate: it validates the entry config at load, so a proposal carrying an invalid node lands as a FAILED fiber and never reaches the commit log." | The harness is a **flat typed-entry tree** (10 node kinds: config / rules / agent_command / skill / code_extension / native_tool / native_hook / native_graph / native_agent / native_loop). Self-mutation proposals are validated by per-kind SHAPE gates **before** the commit log. Flat-tree invariant (grouping entries refused: "the compose loader would mount its children through the same plugins, out of sight of every check that walks the root"). |
| P2 | **Secret-shaped + directive-shaped text rejection at the persistence boundary** | same file: `_SECRET_NAME`, `_SECRET_TEXT` (sk-/ghp_/github_pat_/AKIA/PEM blocks), `_DIRECTIVE_TEXT` (instruction-override phrasings + chat-template control tokens `<\|im_start\|>` etc.). "Tree state persists verbatim … a pasted key in a rule … would outlive rotation in every commit record and published artifact." | A self-evolving store that persists model/code text lints every write for credential shapes and **prompt-injection directive shapes** (directive + object, not topic — "a task about prompts or rules passes"). |
| P3 | **ALWAYS_REVIEWED_KINDS — person review is kind-keyed, not policy-keyed** | `ALWAYS_REVIEWED_KINDS = frozenset({"native_loop"})` — "loop code runs in the loop process with its privileges, and no enforcer stands between it and the host." | Whatever the evolution policy says, **code-shaped mutations always need a person**; data-shaped ones can auto-serve. Review classes keyed on the KIND's privilege, not on confidence. |
| P4 | **Control-flow-as-data admission rules (liveness)** | `validate_native_graph`: closed stage vocabulary; every stage outcome has exactly one edge; all stages reachable from start; every stage reaches an end; **"a cycle without a model stage … nothing would end it"** → refused; patterns run in child processes with a wall-clock (regex `(a\|a)+b` hang noted in-source). | Liveness admission for EXECUTED graphs: (a) every cycle must pass through a budget-consuming stage, (b) no unreachable/dead stages, (c) untestable-termination constructs (regex) get process-isolated timeouts. |
| P5 | **Two-head optimistic release chain over immutable artifacts** | `reef/artifact/release_chain.py`: heads = `current` + `checkpoint`; `advance/install_checkpoint(expected=…)` CAS; `prepare_live` builds a **live child of the durable checkpoint without moving a head**; artifacts content-addressed, immutable. | Versioned delivery of learned state with serve continuity: serving keeps running on the checkpoint head while a live child accumulates; promotion = a two-head CAS install, rollback = repoint. |

## Dedup-grep evidence (workspace, both vocabularies)

- **GEPA-D reflective** (katgpt-rs Plan 164, default-on; riir-ai `.research/146`): evolves config **VALUES** (rubric weights, template hints, bandit params) via Pareto bandit from trajectory reflection. reef mutates **STRUCTURE** (add/remove/replace typed entries). Different axis — complement, not duplicate.
- **MUSE skill lifecycle** (katgpt-rs `.research/172`, ADOPT): 5-stage skill-doc lifecycle with eval-gated registration (~30% rejection). Overlaps reef's `skill` node kind + Grow/Commit; reef's delta = the typed-tree admission layer (P1) + review classes (P3) + release chain (P5). MUSE has no per-kind shape gates and no person-review kinds.
- **`self_evolve`** (riir-clippy): outcome-tier certification (Lemma-4.2 likelihood-ratio gate, Issue 126b), Elo + BetaPosterior selection, lexicographic keep rule — **outcome gates on numbers**. reef's P1/P3 are **shape gates on structure**. Distinct classes; our stack has outcome gates and lacks shape gates.
- **`frontier_miner`** (riir-clippy): proposes corpus additions but they are **oracle-verified** (real cargo clippy) + human batch-committed. reef's admission gates are pre-oracle shape checks that make proposals *admissible*; the oracle remains the quality gate. Composable: shape gate → oracle → person review (P3) → commit chain (P5).
- **Corpus lifecycle / library drift** (riir-clippy Issue 102): tracks drift + cap, but there is **no proposal/commit machinery** for structural self-mutation — corpus changes are human batches only; `--active-set-demote` is a human act by law. The P1/P3/P5 lane is genuinely absent.
- **`MotifAdmitter`** (katgpt-rs `crates/katgpt-core/src/closure/admit.rs`): admission gate but **VALUE-gated** (PRI ≥ 0.1, occ ≥ 3, MDL amortization) for admitting learned motifs as composite primitives. Not a shape gate on structural proposals. Name-adjacent, mechanism-distinct.
- **Freeze/thaw** (katgpt-rs `MerkleFrozenEnvelope` / riir-neuron-db): single-head atomic versioned BLAKE3-checked swap — covers most of P5's need. reef's delta is the **two-head** model (current + checkpoint CAS) and the **live child** (serve continuity during an experimental run). We run single-head; two-head matters only if we serve one snapshot while accumulating a candidate — the riir-ai hot-swap/field-blend surfaces come close. Adjacent, no action now.
- **Behavior FSM** (riir-ai `behavior_fsm`/`behavior_anchor`): runtime code-defined FSMs — no structural admission needed. `FsmPreset` (riir-static-ai) looked like the authored-FSM surface but is a closed 4-variant enum (`Passive | Aggressive | Boss | Custom(String)`) — name is all it has, `validate()` can only check string non-emptiness; a reviewer-verified misaddress (draft issue deleted pre-commit). The real authored-graph store is **riir-scenelab's `ScenarioDag`** (yaml corpus, executed by the runner engine under a run-time-only watchdog/Timeout) — P4's liveness rules apply there at LOAD time, filed as riir-game-sdk `.issues/040`.

## Signal-diff (§3.6) — the one dismissal that needed it

- "Covered by GEPA-D" **rejected**: GEPA-D consumes trajectory-reflection scores and emits *numeric* config values; reef P1 consumes *structural proposals* and admits/refuses on *shape*. A shape gate cannot be derived from a value gate: GEPA-D would happily mutate weights into an entry the tree refuses (e.g., a `rules` entry carrying a credential — P2 — or a `code_extension` bypassing P3's person gate). Coverage claim withdrawn; the lane stands.
- P2 downgraded, not dropped: our persisted stores carry **code spans** (`.heal/`, trajectory store, mining outbox), and the sync boundary already has redaction (`kat_redact` + sync-policy `allow_redacted`). The directive-shaped half targets **prompt-bearing** stores, which we don't persist today. Fold-on-arrival: if a prompt-bearing store ever ships (riir-reflex serving transcripts, gm tooling), the P2 regex class is the write-boundary guard to copy.

## Verdict: **Gain** (architectural — no benchmarkable perf primitive; MOAT: riir-clippy healer moat, "corpus/retrieval structure, trajectory memory, selection math")

One-line reasoning: reef packages a safety vocabulary for letting an agent **mutate its own structure** — per-kind shape gates, person-review classes, liveness admission, two-head commit chains — which is precisely the missing lane between our outcome gates (self_evolve/GEPA-D) and our human-only structural changes (corpus batches, active-set); no GOAT without a benchmark, and the fusion ladder's #2 surface (healer) is the consumer.

Mandatory outputs:
- **Issue (riir-clippy `.issues/136`)** — admission-gated structural self-mutation lane: per-kind shape gates + ALWAYS_REVIEWED class + flat-tree invariant + commit chain, applied to the healer's config/corpus surface; GEPA-D (values) and frontier_miner (oracle) stay as the quality layers above it.
- **Issue (riir-game-sdk `.issues/040`) — CLOSED, landed `e250d77` 2026-09-27** — ScenarioDag liveness admission (P4): refused at the ENGINE ENTRY (tick 0, zero world work) + a public `ScenarioDag::admit()`, with 3 verdict-reviewed corrections vs this row's original wording (edge direction per `check_ordering`; reef rule 1 subsumed by membership + acyclicity — skipped with proof; reef rule 2 literal unsound for parallel-assertion DAGs — replaced by the terminal-sink core). Record: riir-game-sdk `HISTORY.md` 2026-09-27.
- **No plan** — nothing to implement in katgpt-rs itself; P5 is adjacent to shipped freeze/thaw.

## Fusion section (novelty TBD, not claimed)

- **P1 × frontier_miner**: oracle-verified fixture proposals currently enter the corpus only via human batches; an admission-gated proposal layer in between (shape gate → oracle → commit chain) would make the corpus **self-extending with human review only for the review-class kinds**. This is the note's strongest combination; not planned until Issue 136 is triaged.
- **P4 × ScenarioDag × load_scenario**: authored scenario DAGs currently defer all liveness to run time (watchdog/Timeout); admission-time checks catch degenerate graphs at authoring cost instead of run cost — reachability, terminal reachability, **ordering-edge cycles (unsatisfiable by construction — the edges are ordering expectations, not enablement)**, and per-node windows past `budget_ticks`. Cheap, pure, authoring-time. (riir-game-sdk `.issues/040`.)
- **P5 × freeze/thaw**: two-head CAS checkpoint install for riir-ai runtime snapshots — only if serve-continuity-during-candidate-accumulation becomes a real requirement.

## Caveats

- reef is Python infra for LLM-agent harnesses (Claude-Code-class); our "harness" equivalents are the healer's corpus/config and the game static-AI vocabulary — the mapping is by pattern, not by drop-in.
- reef's own recipes (GEPA/TTTD/SAO) wrap third-party methods we already track separately (Research 146 GEPA; TTTD ≈ TTT lane, Research 019/012); this note takes the INFRA vocabulary, not the recipes.
- Unread at verdict time: `reef/train/` (Slime batch plumbing), `reef/service/` (serving/leases), docs/rfcs — none gate the verdict; the five primitives are pinned from `harness/tree/nodes.py` + `artifact/release_chain.py` at the pinned sha.
