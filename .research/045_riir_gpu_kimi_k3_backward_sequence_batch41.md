## The 6 rules

1. **`concurrent-disjoint-write-buffer-parallelizes-uploads` (E)** — a large host→device upload serialized on one thread is host-bandwidth-bound, not device-bound; native wgpu backends do NOT serialize `queue.write_buffer` calls targeting disjoint offsets, so one big upload splits into 256-aligned chunks written concurrently from rayon workers (~8× per-layer update parallelism, ~49ms → ~8ms on M3 Max). Chunk size must round UP to `COPY_BUFFER_ALIGNMENT`; fall back to a single write below 2 chunks. Source: `weight_buffer_cache.rs` L237-257 (`parallel_write_buffer`) + `kimi_k3_gpu_backward_sequence.rs` L546-555 (per-layer `rayon::scope` docs) + `kimi_k3_gpu_backward.rs` L342-345 (3-matrix parallel transpose).
2. **`aliased-slot-allocate-replace-fallback-severs-binding` (A)** — the B39 boundary condition: a two-tier in-place cache slot built from a handle CLONE (`from_handle`, aliasing a handle owned by another struct) must treat "raw view unavailable" as a hard error — the allocate-replace fallback writes into the slot's OWN fresh allocation while the consumer keeps binding the ORIGINAL handle, so every subsequent update is orphaned and the consumer silently reads boot weights forever. On `cuda_backend` (`extract_buffer` = no-op `Ok(())`) the fast path can never engage → EVERY update takes the severing fallback. Source: `weight_buffer_cache.rs` L158-161 + L128-132; `kimi_k3_gpu_backward_sequence.rs` L478-481 + L527-535; systemic per-layer instance `kimi_k3_gpu_backward.rs` L321-325.
3. **`pool-slot-write-coalescing-owns-only-declared-ranges` (A)** — the writer-side complement of B40's build-side rule: when N cached slots are sub-allocations in pool-managed buffers, per-slot writes coalesce at runtime (group by parent buffer, sort by offset, merge exact-adjacency runs into ONE staging copy + ONE write) — but a coalesced write may cover ONLY the union of declared slot ranges; gap bytes may belong to OTHER pool tenants. Contiguity is an opportunistic pool-placement property the writer must DISCOVER, never assume. Source: `weight_buffer_cache.rs` `write_slots_batched` L263-283 + L309-311 + L325 + L334-335 + L415-416 (~246 calls/step → a handful).
4. **`pool-reservation-token-outlives-raw-view` (A)** — a cached raw sub-allocation view (native buffer + offset) is NOT an ownership token; the wrapper `Handle` owns the pool reservation. Drop the handle → the manager marks the range free and RE-ISSUES it → the still-alive raw view aliases a different tenant's bytes. The handle field looks vestigial (nothing binds it) but deleting it corrupts unrelated tensors. The OPPOSITE direction of B21's pool-movement staleness. Source: `weight_buffer_cache.rs` L40-43 + L56-62.
5. **`gpu-type-bridge-borrows-not-clones` (A)** — bridging CPU reference types to GPU module types by cloning the saved-activation payload multiplies memory traffic per layer per step; the worst shape clones TWICE (owned copy of the source collection, then a converter that field-clones again — the first clone 100% dead when the converter takes `&T`). GPU "backward saved" types are frequently field-identical to the CPU types: borrow instead. Where the callee's owned-slice API forces the clone, fix the API (`&[&T]`), not the clone. Source: `kimi_k3_gpu_backward_sequence.rs` L892-896 (MLA double clone, `all_saved_cpu` dead after the map) + L1082-1095 (Dense 4-field clones) + L941-943 (KDA, API-forced) + L1179-1227 (converters clone every field, zero transformation).
6. **`superseded-primitive-machinery-zombie` (A)** — when a composition path replaces a per-module GPU primitive (per-token GEMV → CPU batched primitives), the superseded primitive's support machinery (pre-built handle, per-step transpose + re-upload pipeline, caches, staging buffers) keeps executing every step because its lifecycle hangs off a long-lived struct's update schedule. The tell: the superseded fn's only remaining caller is its own parity test. A maintained-but-never-read `pub` handle is invisible to dead-code lints. Source: `lm_head_backward_gpu` (`kimi_k3_gpu_backward.rs` L457, sole caller = its own test L3617) + the zombie machinery (`kimi_k3_gpu_backward_sequence.rs` L476-481 boot build + L489-526 per-step 640 MB-class staging upload + GPU transpose dispatch; L281-286 staging buffer sized `hidden*vocab*4`) vs the real production LM-head path (CPU `batched_transpose_matvec` L735-741 + `batched_outer_product_acc` L790-796) + the stale header doc-lie (L13) + riir-train's stale justification (kimi_k3_train.rs L2200-2210).
