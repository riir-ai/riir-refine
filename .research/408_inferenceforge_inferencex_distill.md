## What the source is

A recursive-self-improvement loop for inference serving: custom environment + harness + eval suite around an off-the-shelf coding agent doing **SLA-aware** serving optimization. The loop: measure (cache hit rates, per-kernel time) → write its own test scripts and microbenchmarks → identify the biggest bottleneck → implement a targeted fix → validate. Headline: under a 30 tok/s per-user SLA, K3 serving pushed to **12.8k tok/s per GPU, 43% above** the best published AgentX reference meeting the same bar (8.9k) — **9 iterations over 3 days**; peak 16.2k (29% above the best published, no SLA). K3.1: 23.7k at 56 tok/s per user, 5% above the published best (22.6k) while faster per user. GLM-5.3: +12% per GPU at the published peak (Dynamo), p90 TTFT 4.5 s vs 13.2 s. The blog's own framing of WHERE the gains came from is the mineable part: "Three fixes contributed most of the gains," each a serving-stack PR with a mechanism-level kernel number.
