# cargo-refine — a code healer for your coding agent

`cargo refine` is a modelless code healer that runs inside any Rust crate: a drafter + pruner over a shipped lint corpus, no LLM, no telemetry of your source. It reviews code, suggests bounded fixes, and applies them with a compile gate.

- Bare `cargo refine` is the DRY RUN — zero edits, zero sends.
- `cargo refine fix` WRITES by default — the explicit verb is the consent.

## 2. The golden law: dry run first, fix second

```sh
cargo refine                    # DRY RUN: review what would be fixed — zero edits
cargo refine src/ crates/foo/   # scope the review to paths
cargo refine suggest            # the explicit review command
cargo refine fix                # REAL FIX: writes in place + compile-gates
cargo refine fix --no-verify    # skip the compile gate (fast, syntax-checked only)
cargo refine fix --verify-args "--features a,b"   # verify gated code at its real set
cargo refine --quiet --fix      # skip the review pass (only show fixes)
cargo refine --yes --fix        # non-interactive: every y/N prompt answers yes
```

- The bare dry run is private: no account, nothing written, nothing sent.
- **Verb-first**: the docs teach the verbs (`fix`/`suggest`/`fix-compile`). The old `--fix`/`--suggest` flag spellings stay accepted as quiet aliases — existing scripts keep working — but teach the verbs.
- rustfmt follows automatically when the file was already rustfmt-clean (pre-existing drift and CRLF files are skipped) — no formatting churn enters a mechanical diff. `--no-fmt` disables.
- Allow-by-default lints (pedantic/nursery) are fixed only where the target crate enables them or their group; otherwise they are skipped loudly. `fix --groups pedantic,nursery` restores apply-everything for those groups.
- `--top-k <N>` caps the per-span suggestion list (default 3 per domain) — raise it when hunting a fix the ranking missed.
- Commit the fix separately: `fix: refine <repo> <scope>`.

## 3. The oracle: clippy anchors the suggestions

Over a cargo project, a scan auto-runs clippy (`cargo clippy --workspace --no-deps --message-format=json`) and uses real diagnostics to anchor suggestions:

- spans clippy flagged surface FIRST, marked `[oracle]`, with the corpus fix;
- diagnostics with no corpus rule surface as `[no corpus rule]` (a live gap signal, not an error) — `--corpus-delta` partitions them into "not leased yet" vs "unsupported";
- covered spans clippy said nothing about are stamped `[heuristic]` — the false-positive datum; treat them as leads, not verdicts.

Knobs: `--all-targets` is the DEFAULT posture (test-module spans are where fixture code lives). `RIIR_REFINE_AUTO_ORACLE=0` restores never-spawn; `RIIR_REFINE_AUTO_ORACLE_FEATURES=<csv>` re-aims the spawn at a non-default feature set; gap-arming (the default) runs up to 3 extra passes over targets whose required-features the base pass did not enable — `RIIR_REFINE_AUTO_ORACLE_GAP_ARM=0` restores single-pass. `cargo refine oracle-census` prints the blind-spot report without compiling. Manual feed: `cargo refine suggest --clippy-json <path>` (the `--message-format=json` stream). Non-cargo directories run heuristic-only, loud.

## 4. Verify at the real feature set

`fix` compile-gates by default on release builds: baseline check → apply → re-check → auto-revert the offending edits. The gate runs at the invocation's feature flags — a default-features verify compiles cfg-gated files EMPTY, so a green check proves nothing about them. Pass `--verify-args "--features <set>"` covering the edited files' gates (grep the enclosing `#[cfg(...)]`).

Four post-verify disclosures name the exact re-run for kept edits the posture provably did not compile — read them when they print: the **cfg audit** (edits inside cfg-gated regions), the **required-features audit** (edits in a test/bench/example target whose features are unsatisfied — `--all-targets` skips those silently), the **module-decl audit** (a `#[cfg]` on the file's `mod` declaration), and the **unverified-kept audit** (a kept edit under a failed final check). Kept edits any of these name are recorded `verified=false` — never certified.

## 5. What stays manual

The healer is deliberately SILENT (never wrong) on its documented divergence classes — fix these by hand:

- comment-guarded matches (a match whose arms carry guarded comments),
- array-literal defaults,
- named-argument renames,
- nested macro arguments.

Also manual: semantic lints, anything needing a design decision, and **bench files** — perf rules are measurement-altering on bench targets, so `fix` declines them with a loud `bench-guard:` line per file and `suggest` stamps `⚠ bench-guard`. A bench file's numbers ARE its artifact; hand-edit those.

## 6. The repo-posture fix (heal a repo you do not own the style of)

```sh
cargo refine fix --clippy-json feed.json --repo-posture
```

Clippy-lane edits land ONLY where the target repo's own clippy flagged the span. Requires a feed (the auto-oracle or `--clippy-json`); without one it refuses. Use when healing a foreign repo: never restyle code its gate never complained about.

## 7. Compile-error repair lane

```sh
cargo refine fix-compile                 # review: prints the plan
cargo refine fix-compile --write         # apply: keep/revert per attempt
cargo refine fix-compile --write --verify-args "--features <set>"
```

Coded rustc errors via playbooks (the E0597 family today; other codes report as misses). Bounded by `--max-iters` (default 5). Bench targets guarded the same way — name the file explicitly to override. Every `--write` run dumps an ordered per-attempt ring to `<repo>/.refine/fixseq/run-<ts>.jsonl` and the misses queue to `.refine/misses/` — both are files on YOUR disk; read them before re-running a stuck lane.

## 10. The contribution loop (free, opt-in)

Fixing is always local and free — no account, no network. Contributing your redacted fix records to the shared corpus (and getting public credit) is opt-in:

```sh
cargo refine join      # opt in: the contribution policy + a read-only GitHub check,
                       # binding your random client ID (public credit + leaderboard)
cargo refine rank      # the leaderboard (joined identities only)
cargo refine info      # what the network fixed, by domain (counts only)
cargo refine corpus    # corpus state + the freshness offer
cargo refine update    # corpus lease refresh (auto-runs ≤ once per 12 h)
cargo refine sync      # push redacted batches + pull the lease
cargo refine leave     # undo the join — nothing more is sent
```

- Joining is one command and reversible (`cargo refine leave`); local healing is identical joined or not. Every record leaves secret-scanned (a finding drops the row), never whole files, never your paths. Proven pairs join the public MIT corpus; the corpus leases back to every machine's retrieval.
- Contribution points are non-transferable, expiring reputation — never payment, never a token; they can never be bought, sold, or traded.
- `--stats on` is a separate consent (per-run rule VOCABULARY + counts, never spans, source, paths, or repo names). Contribution and stats are independent; neither implies the other.
- Offline / unreachable service never fails a heal run — the contribution tail degrades loudly; healing is local. `cargo refine offline` is the hard firewall (marker-based; env vars and settings.toml cannot override it until `cargo refine online`).
- A depleted shared-corpus account gets a soft gate — a refusal naming the two refuel paths (contribute or top up); the refusal itself names the opt-out env, and the metering plane has its own disable env.

## 11. Service URL

`cargo refine config get` prints the ACTIVE service URL and its source (env > config > default). The default dials the production network:

```sh
cargo refine config set --url devnet    # pinned alias (also: mainnet)
cargo refine --net devnet ...           # one-invocation env sugar
```

`RIIR_REFINE_KAT_SERVICE_URL` overrides everything for one invocation. `cargo refine config adopt-state <devnet|mainnet>` migrates pre-split network-blind state — oracle-confirmed adopt or quarantine, never auto.

## Traps we already paid for

1. **`fix` writes.** Review = bare `cargo refine` or `suggest`. The pre-2026-09-08 docs called the fix flag the dry run — they lie.
2. **A green verify over cfg-gated code proves nothing** without `--verify-args` — gated files compile empty at default features (§4).
3. **The four divergence classes never auto-heal** (§5). Forcing them by hand-editing the corpus rules produces wrong edits; that silence is the design.
4. **Bench files are declined on purpose** — their numbers are the artifact. Do not un-guard a `bench-guard:` decline.
5. **A silent heuristic-only run is the loud fallback's failure** — if clippy could not run, the run TELLS you; don't cite its ranking as oracle-anchored.
6. **The crates.io build is code-fixing only.** `cargo install riir-refine` fixes code; `join`, the leaderboard and latent retrieval ship in the prebuilt binaries; the installers verify SHA256SUMS.
7. **The mining surface is gone.** `--mine`/`--unmine`/`--purge` do not exist — old docs naming them are stale. `cargo refine join` / `leave` is the contribution surface, and the run-end CTA is join.
8. **The production network is the default dial.** The prebuilt binary is net-pinned; `--net devnet` and off-mainnet env overrides refuse at runtime naming the pin. Money verbs are operator lanes, not healing lanes.
9. **The installer never logs in for you.** Local healing needs no account; the first consent question is answered on YOUR terminal, never pre-seeded.
