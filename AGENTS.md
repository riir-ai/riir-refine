## Guard-landing protocol — a guard is not landed until the residue is counted

Landing a proposer guard stops the rulewright **emitting** a broken class. It does nothing about what the un-guarded rulewright already emitted and that already landed in consumer repos. **The rule:** on landing a guard for class C, run the sweep and paste its table into the landing note. Fix or file — never silently leave it unmeasured. (Measured basis: the `227637e` guards were correct yet 32 pre-guard residue sites landed in riir-ai the next day.)

```bash
scripts/consumer_residue_sweep.sh <lint> [<lint> ...]        # the screen
scripts/consumer_residue_sweep.sh --grep '<regex>' <lint>    # narrow first
```

Target set: `scripts/swept_repos.txt` (derived from the BOUNDARY.md workspace, worktrees excluded — the file documents how to re-derive it). Exits non-zero when residue exists. **The screen is the claim**: `cargo clippy --workspace --all-features --all-targets --keep-going` — not `cargo check` (the guarded classes pass check's typeck, so the rulewright's own `--verify` gate is blind to them), not default features (residue sat behind non-default ones). The script `cargo clean -p`s each member inside a sweep-local `CARGO_TARGET_DIR` so a cached build cannot print a quiet zero, and prints a per-repo diagnostic total as a liveness witness. (Story + JSON-shape traps: `HISTORY.md`.)

## Source secrecy & binary-only distribution (non-negotiable)

## Why this is a separate repo (not in riir-ai)

Borrows the **drafter+pruner+corpus pattern** from `riir-games-quest/quest_grammar` but has **zero game-domain coupling**: no dep on `riir-games*` / `riir-game-sdk` / any game crate from ANY feature combination; no `riir-chain` dep; default build's only public dep is `katgpt-core` (ConstraintPruner trait + ternary SIMD matvec + `pick_domain`); opt-in arms consume non-game sibling substrates (`ternary_inference` → `../riir-infer`; `latent_retrieval` → `riir-rag` in riir-neuron-db; `bonsai_retrieval` → `riir-rag-bonsai` in riir-ai); the `TernaryDraftModel` pattern is reimplemented locally (~200 LOC). riir-ai is for game runtime + engine, not developer tools.

## Numbering Discipline

Issue, plan, doc, benchmark, and research numbers are **monotonic and never reused** — even after a file is removed per the noise-reduction rule. Same for `.plans/`, `.docs/`, `.benchmarks/`, `.research/`, and `.distill/` (the distill-program rolling resume state — edit-in-place per batch, NOT one file per batch).
